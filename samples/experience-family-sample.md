# 读数可信度族

> 一句话：**当你要用某个读数下结论时想起它** —— 先问"这个数是从哪来的、还作数吗"。
> 与 `PITFALLS` 的关系：覆盖 P97（判据的证据源被截断）与相邻的"0 命中/全绿误读"类。

## 覆盖的坑（成员声明）

**覆盖的坑（成员声明）**：P97（共 1 条）

## 先对号入座

| 现象（你会看到什么） | 大概率是哪一类 |
|---|---|
| 检索/召回**命中 0**，于是断定"库里没有" | 证据源被截断（query 被切词 / 日志被轮转 / 输出被编码改写） |
| 检查**读数全绿**但退出码非 0 | 脚本末行输出在窄编码终端抛异常 |
| 语料改了但读数掉了 | **代际不同**（语料/索引/期望集三代没对齐） |
| 日志一夜间小了 | **被轮转**了，历史事件在 `.gz` 里 |

## 做法（照做即可）

1. **先验证据源还在不在** —— 文件非空？跨不跨归档？query 能分词？退出码真 0？
   **判据**：对每个"0 / 空 / 全绿"，能说出证据文件的**当前大小与最后写入时间**。
2. **对齐代际再比较** —— 报读数必须同时报**语料指纹**；两次读数指纹不同就⛔ 不比。
   **判据**：读数旁边有 `fp` 字段。
3. **轮转/截断类动作要同步改判据** —— 判据读归档，不是只读现役文件。
   **判据**：删/移证据文件后，判据仍能给出与非删除前一致的结论。

## 判据 / 自检

```
① 每条结论都挂着"证据文件 + 当前指纹/大小"吗？
② 有没有把"0 命中"直接读成"没有"？（没有 ≠ 没找到）
③ 两个读数放一起比时，fp 一样吗？
```

## 边界（⛔ 不适用的情况）

- 一次性的人工查看（不写结论、不入账）—— 不必上这套流程。
- 读数本身就是**目标值**（如"交付 N 个缺陷"），不存在证据源问题。

## 证据

- 真实样本：`PITFALLS.md` 的 P97 条（现象 / 触发条件 / 处置 / 来源四栏齐全）
- 读数：同一条坑在 `_capability_choice_lint.py` 上实测 **FAIL → PASS**（读归档后）
