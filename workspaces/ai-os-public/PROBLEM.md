# PROBLEM — AI-OS 想解决什么

> 本文只回答三件事：要解决什么真实问题、为什么现有做法不够、边界在哪（不解决什么）。
> 「是什么 / 怎么工作 / 怎么接入」见仓库根 [`README.md`](../../README.md) 与 [`QUICKSTART.md`](../../QUICKSTART.md)。

## 一句话

Agent 的失败，多数不是"能力不够"，而是能力 / 知识 / 经验**在需要的那一刻不在场**；即使在场，也常常没被用。

## 一、真正的瓶颈是"送达"，不是"供给"

给 Agent 加能力这件事，今天的成本已经很低：多写几个工具、多放几份文档、多建一个知识库，都能做到。
但**存在不等于被用**：

- 工具挂在工具表里，Agent 22 次调用里 0 次碰它，推理里也从未考虑过它。
- 规则写进宪法，Agent 读过、点头、然后不执行。
- 能力文件写得再好，它躺在目录里，而 Agent 不知道此刻该找谁。

所以问题不在"再建一个能力"，而在**送达**：

1. 机械动作能不能**不依赖 Agent 记得**？
2. 材料能不能在它**真正会停下来的时刻**自己出现？
3. "用没用、有没有用"能不能留下**可复核的证据**？

## 二、四道断点

一条能力要真正起作用，必须连过四道：

| 断点 | 失败长相 | 本项目的主张 |
|---|---|---|
| **存在 → 被用** | 能力建好、没人调；工具在表里、不在决策里 | 不靠自觉：把介入点放到 Agent 工作流的确定性时点上（开工恢复、占卡后、改动后、收口时） |
| **被用 → 被读** | 调了工具、返回一堆候选、一条也没打开 | 注入要短（路径 + 一句纪律），并且**跟着卡上的声明**走，不猜它想什么 |
| **被读 → 有价值** | 读了、照做了、产出没变好 | 只承认机械字段：是否进 diff、返工是否减少、移除后是否明显退化 |
| **环境变强** | 同一个坑踩第二次、第三次 | 把真实工作里的坑沉淀成经验族卡与坑清单，让下一轮开工能召回 |

四道都过得去，一条能力才算数。**本项目的难点全在这四道断点上，而不在"能不能建"。**

## 三、为什么现有做法不够

主流解法是"给 Agent 加能力"——更多工具、更全文档、更大知识库。这条路解决的是**供给**，而失败发生在**获取**：

| 已有做法 | 它解决了什么 | 在哪儿失效 |
|---|---|---|
| 写进宪法 / 规则 | 规则可见 | 没有落点就不执行：纪律不能当机制 |
| 建更多能力 / 知识 | 供给变多 | 建得越多越依赖"被想起"；存在 ≠ 被用 |
| 靠 Agent 自觉 | 成本低 | 最有利条件（它在自己仓里、刚改过它的 hook、判据就在手边）下仍然不主动 |
| 检索 / 推荐 | 按需发现 | 触发 → 返回 → 打开 → 采纳，链条每多一环就多一次漏 |
| 扩语料 / 调权重 | 召回变宽 | 命中往往只是"长正文 × 通用词面"的表面相关 |

反复付代价的同一个误判是：**把"机制存在"当成"机制生效"**——静默失败、假绿、`exit 0` 跳过。
AI-OS 的设计因此有一条贯穿性要求：**失败必须可查**（探针至少落一条，空输出不能当零结果）。

## 四、边界：不解决什么

明确的"不做"清单（是范围约束，不是谦辞）：

- **不解决模型能力**：不训练、不微调、不做推理增强；模型强弱是外部变量。
- **不替 Agent 判断**：适用性、采纳、拒绝归 Agent；AI-OS 只负责让材料到场。
- **不追求能力数量**：存在 ≠ 值得建；过不了"移除后是否明显退化"的东西不建。
- **不做通用记忆库 / 知识库 / telemetry**：不建重复事实存储。
- **不做多 Agent 编排 / 通用调度平台**：当前只把"检索 + 投递"这一条链做到底。
- **不做"全自动"**：机械动作 → runtime；判断 → Agent；架构决定权 → Human。

## 五、哪些是假设（🟡 未验证）

以下问题**看起来成立，但还没有足够证据**；不得写成已知：

| 假设 | 现状 |
|---|---|
| 事件提醒能改变 Agent 的行为 | 🟡/反例：注入**到达**可证，但"成为决策输入"在若干轮真实任务里为 0；改形态 / 条数 / 相关性 / 时机都没改变它 |
| 经验召回能减少重复踩坑 | 🟡：机制在跑、触发正则在修，但"同一坑第二次是否还踩"缺机械读数 |
| "打开率提升"会带来价值 | 🟡：打开可达且会照做，但"照做后产出更好"缺判据；能力侧不以打开率判成败 |
| 多能力 / 多阶段编排有收益 | 🟡：未建、未测 |
| "真实工作反过来让环境变强"能自动闭环 | 🟡：提醒半环可复核，写回半环仍靠 Agent 手做 |

## 六、怎样才算解决了

判据先于实现：

1. **可回源率 100%** —— 每条候选都能指回具体文件与行，否则不谈价值。
2. **独特发现率 > 误报率**（N≥20）—— 只是把 Agent 已经知道的再给一遍，不算。
3. **移除测试** —— 去掉它，工作是否明显退化。
4. **不用 Agent 自报** —— 只看机械字段：调用数、候选被打开次数、是否进 diff。
5. **验证权外置** —— Human 抽查 / 独立 Agent 对照实验，Agent 不自证。

判据的完整证据与"不证明什么"见 [`EVIDENCE.md`](EVIDENCE.md)。
