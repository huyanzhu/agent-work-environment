# EVIDENCE — 证据有多硬

> 本文只回答两件事：**有什么证据**、**证据有多硬**。原理与边界见 [`README.md`](README.md) / [`PROBLEM.md`](PROBLEM.md) / [`PRINCIPLES.md`](PRINCIPLES.md) / [`METHOD.md`](METHOD.md)。
> 每条的判据是**能否回源**（文件 + 命令 + 读数），不是结论多好听；指不回的一律不进本文。

## 〇、四档口径

| 档 | 含义 | 能支撑到哪 |
|---|---|---|
| **A 实测读数** | 探针 / 脚本可重算的机械字段 | 「现象存在」，换人可复核 |
| **B 单批次样本** | 一次实验或一次真实任务 | 「发生过」，⛔ 不作趋势 |
| **C 方向性论断** | 多次读数同向、无对照实验 | 只给方向，⛔ 不写「已验证」 |
| **D 反例** | 假设被读数推翻 | 「假设不成立」，用来防过度声称 |

四档依次变软。**与对外口径的映射**：A → ✅ 实测 · B/C → 🟡 未验证 · D → 反例。
本文的 ✅ 只到「机制可复核」，**不到**「价值已证明」。

## 二、B｜单批次样本（发生过一次，不作趋势）

1. **能力内容作为方法清单，在单次对照里有正向读数**：同一份站点快照、同一份零清单任务书，读能力文件并照做的一臂
   改到的缺陷类别是"只凭自己判断"那一臂的**严格超集**。⚠️ 边界：N=1/臂；治疗臂的任务书多一句"按能力文件做法清单做事"⇒ 混入指令效应。
2. **能力文件被打开后确实会照做**：几次真实任务里，被 read 的能力条目都进了后续动作。
   但**全部发生在"必须作答"的流程项之下**，不是"打开率自然提升"的产物。

## 三、C｜方向性论断（有方向、无定理）

1. **送达是机制问题，不是纪律问题**：最有利条件下（在 AI-OS 仓内、刚亲手改过它的 hook、判据文档在手边）仍不主动 ——
   `task_start` / `experience_push` / `capabilities` 全未走。单调性给方向，不是因果证明。
2. **写回不能靠「记得」**：手工写回在几次真实任务里 0 次被调用（两个不同执行者）；挂上 hook 后才闭环。
3. **必要性是唯一开关**：纯靠提醒的注入收效为 0；加一个"必须作答 + 必须有证据 + 必须真打开"的流程项后明显改变行为。
   样本小，只到方向。
4. **流程固定，能力不固定**：固定"必须作答 + 必须有证据"，不固定"选哪个"——不同任务各自选了最贴合的域能力。
5. **越往后越软**：机制（调用 / 到达 / 写回）可机械复核；价值（是否真帮到 Agent）目前全部停在 🟡。

## 四、D｜反例（被证伪的假设）

> 这一节是本文最有价值的部分：它记录的是**已被读数推翻**、但仍然常见的假设。

1. **「能力在开工时注入就会被用」⇒ 被证伪**：多轮真实任务里注入了数十次能力，**成为决策输入的为 0**；
   改形态 / 条数 / 相关性 / 时机都不改变这个 0。注入 top1 与最终被选能力几乎不重合，Agent 更常自己挑贴任务的能力。
2. **「把约束句放进工具返回就能让人打开」⇒ 投放点错位**：不调用那个工具就永远看不到；子代理触发率 0/1。
3. **「首拍注入更及时」⇒ 被证伪**：会话第一拍的 topic 被首条用户消息污染，top1 与当时工作无关；
   首拍注入现已**默认关闭**（代码保留可回退）。
4. **「Exposure 五模式在运行」⇒ 被证伪**：五个模式名在执行层引用 0 处；8 个域能力里 0 个有 `condition:` 字段；
   `Assembled` 无装载器 ⇒ 对外叙事降级为"设计词汇"。
5. **「打开 0 次 ⇒ 真没打开」⇒ 观测口径错**：探针用子串匹配路径，Windows 反斜杠路径大面积漏计；
   换严格口径后"0"变成非 0。**读数口径本身也会假。**
6. **「AI-OS 是完成任务的必要条件」⇒ 拿到反向证据**：一个完全不用它的干净子代理也能交付，并找出真实缺陷。
   **这条质疑的不是机制，而是这套东西是否必要。**
7. **「投递通道在产生价值」⇒ 被压到「只止血」**：声明驱动把"猜错域"换成"判对域"，噪音消失；
   但开 / 关两臂的产出一致 ⇒ **判对域 ≠ 产出更好**。
   ⚠️ 机制耦合：关掉域注入**不等于不注入**，而是回落到检索候选注入；想测"完全无注入"必须同时关阶段注入或移走总闸。

## 五、这份证据不证明什么

- **不证明 AI-OS 有用**：A 档只证"现象存在"；能力价值五问多数仍是 UNKNOWN。
- **不证明检索有价值**：能证明的是"注入判对域"与"内容有据"；"被消费 → 变成产出"仍未证（只止血）。
- **不证明因果**：对照实验 N=1 量级；方向一致 ≠ 机制成立。
- **不证明可迁移**：现有读数来自**单机、单平台**（Windows + PowerShell）；未在别的环境复跑。
- **不证明数字稳定**：探针跨会话累积，口径有已知缺陷（路径漏计 / 非零退出不算错误）；换口径读数会变。
- **不证明流程项是唯一解**：n 很小，且未排除新奇效应。

## 六、想自己造一个可核的读数

```bash
python tools/probes/_clone_selftest.py     # ① 先确认包本身是好的
# ② 引一条能力，照它做一件小事
python tools/task_card.py create "<你的任务>" --project=示例
python tools/task_card.py claim 示例/<TASK-ID>
python tools/task_card.py capability 示例/<TASK-ID> --name <域能力> --why "<≥8 字理由>"
# ③ 收工时在卡的 Outcome 里写：用了哪几条做法、哪条是本来不会做的
```

**判据**：撤掉某条能力做法后，交付质量没有明显变差 ⇒ 这条能力对你是噪音。按移除测试自行裁剪——这是这套东西最希望被外部检验的地方。
