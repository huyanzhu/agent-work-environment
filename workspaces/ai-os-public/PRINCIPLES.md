# PRINCIPLES — AI-OS 的设计原则

> 原则不是愿景，是**已经付过代价的行为约束**：每一条都能对回一次真实故障、一条读数、或一个可机械校验的条款。
> 对不回证据的话不写在这里——它们要么进 [`PROBLEM.md`](PROBLEM.md)「假设·未验证」，要么先不做。
>
> **读法**：每条 = 原则 → 它约束什么 → 证据 → 违反的代价。

---

## 一、可验证优先：先问「删掉它，工作会不会明显退化」

**原则**：任何能力、机制、结构在存在之前，先回答"移除测试"；答不出来的不建。

- **约束**：新建 = 先写清"移除后谁退化、退化在哪"；写不出 ⇒ 不进建设队列。
  三条纪律：**存在 ≠ 值得建**；**方向性 ≠ 已验证**；**单批次 = 未验证**。
- **证据**：这条约束真被用过——对一组计划中的结构逐项做移除测试，结论是"换个人做不会退化" ⇒ 决定**不建**那层中间结构，并撤掉了数项已计划的结构。
- **违反的代价**：建了就要维护、要被想起；而"被想起"正是下一条要处理的失败。

## 二、送达优先：建好 ≠ 到场，送达是机制问题

**原则**：判断一个东西有没有用，不看它存不存在，看它在 Agent 真正会停下来的时刻有没有自己出现。

- **约束**：① 经验 / 能力文件名必须**任务显式相关**；② 入口文档是启动顺序，必须点名下一步；③ 送达点落在 Agent 的动作前后，不靠它自觉去翻。
- **证据**：反例可复核——工具表里排到第 31 位的工具，22 次调用里 0 次被调，推理里也从未提及；`AGENTS.md` 明写"开工先检索经验"，实际仍不执行。
- **违反的代价**：能力**存在 ≠ 被用**。可观测的只有"注入判对域"，"被用 → 变产出"仍未证。

## 三、状态锚：卡是快照，日志是流水；事实与方向分层

**原则**：工作记忆要在被读取的那一刻读得懂、读得全。

- **约束**：① 卡只留 `Goal` / `State` / `Next Action` / `Resume Point` 等可扫读字段，占用与收尾留痕写**同级 `.log`**；② `State` 取 9 态值域内的值，首个 token 就是值本身；③ **已核实事实** 与 **建议方向** 分开写，方向一律标"未核实 / 待验证"；④ 项目级状态进项目文件夹的 `PROJECT.md`。
- **证据**：一次真实故障——某张卡长到 5 万字节，`Event Log` 落到了 Runtime 只读尾部窗口之外 ⇒ 占用判据**恒为空**，焦点卡 / 投递 / 唤醒全部静默失效，且**零报错**。治本做法是把流水外置到 `.log`，并让读写两侧同步。
- **违反的代价**：卡一变长，不是"读得慢"，是**读不到且不报错**；下一个会话拿到的"焦点卡"是空的。

## 四、写回要有显式完成标准，不靠"记得要写回"

**原则**：收尾不是"我觉得做完了"，是一组能逐条勾的完成标准；写回动作由机制触发，不由记忆触发。

- **约束**：收工必须填 `Outcome` / `Confidence` / `Knowledge Used` / `Deliverables`，并逐条过 `Close Checklist`；缺项显式写缺，不写"基本完成"。
- **证据**：① 纪律失败可复核——手工写回在连续几次真实任务里 **0 次**被调用（两个不同执行者），挂上 Stop hook 后才闭环；② 条款可机械校验——能力选择的三行记录只从 `.log` 读，出 PASS / FAIL / SKIP。
- **违反的代价**：没有完成标准的"完成"无法复核，也无法判断该不该归档；`Completed` 会退化成"停止"的同义词。

## 五、结构从需求长出来，不为"像 OS"而建

**原则**：名字可以先于实现，结构不能。没有被真实需求逼出来的层、目录、字段，一律不建。

- **约束**：① 不建 telemetry（引用 = 足迹协议）；② 不建重复事实存储；③ 不预测、不预建平台；④ **设计词汇 ≠ 上线功能**，对外叙述必须区分。
- **证据**：对外叙事里**不再**写"我们有五种出现方式"——逐项盘查后：五个模式名（Exposure 五模式）在执行层引用 0 处、8 个域能力里 0 个有 `condition:` 字段、`Assembled` 没有装载器 ⇒ 降级为**设计词汇**。规模（8 域 / 50 片 / 112 条坑）是**现状读数**，不是里程碑。
- **违反的代价**：多一层结构就多一份必须送达的东西；而"送达"已经是本项目反复失败的那一格。

## 六、验证权外置：验证者不能是被验证者

**原则**：Agent 可以自检，但**不能自证**；"有没有用"必须由机械字段、独立 Agent 或 Human 判定。

- **约束**：① 价值判据只用机械字段（调用数 / 候选被打开次数 / 是否进 diff），不用 Agent 自报"我采纳了"；② 小样本先由 Human 判几条，标准稳了再放宽；③ 可回源率 100% 是谈价值的前置。
- **证据**：自报被轨迹证伪过——同一会话里 Agent 自报"采纳 2 条"，机械字段显示候选文件打开 **0 次**。
- **违反的代价**：读数会退化成"Agent 说它有用"。

## 七、用法与边界

- **用法**：评审一处改动，逐条问「它违反哪一条？」；违反要给出证据与替代方案，而不是给理由。
- **本文不写的**（有讨论、未采纳或未验证，⛔ 不当原则用）：
  - "主动引导 Agent"：已明确不投入；
  - 多能力 / 多阶段编排：未建、未测，不预建；
  - "真实工作自动让环境变强"：维护提醒在跑，写回仍手做；
  - 经验召回减少重复踩坑：只有方向性读数；
  - "打开率提升会带来价值"：打开是消费的必要条件，不是充分条件。
- **一条总纪律**：本文的 ✅ 只到"机制可复核"，不到"价值已证明"。
